# 指示書04: メール受信（添付ファイル自動取り込み・Phase 2）

## 目的
FAXしか使わない・Webが苦手な出展社向けに「専用メールアドレスに書類を添付して送るだけ」の提出経路を作る。
設計docsではF-03（将来対応）。**着手前に大西さんへ「専用メールアドレスをどのドメイン/サービスで用意するか」を確認すること**（下記の確定設計はGmail前提）。

## 確定設計

### 方式: Gmail API ポーリング（推奨・確定）
Webhook方式（SendGrid Inbound等）は受信ドメインのMX設定が必要で運用が重いので採らない。
専用Gmailアカウント（例: `dosl-hub-docs@gmail.com`）をポーリングする方式にする。

- バックエンドに常駐タスク（FastAPIのlifespanで `asyncio.create_task`）を追加し、
  `MAIL_POLL_INTERVAL_SEC=120` ごとに未読メールを取得
- 認証: Gmail API のOAuthリフレッシュトークンを .env に置く
  （`GMAIL_CLIENT_ID / GMAIL_CLIENT_SECRET / GMAIL_REFRESH_TOKEN`。
  トークン取得はローカルで1回 `scripts/gmail_auth.py` を書いて実施し、値だけVMへ）
- `MAIL_INGEST_ENABLED=true` のときだけ起動（デフォルトfalse＝ローカル開発に影響なし）

### 取り込みロジック（services/mail_ingest.py 新設）
1. 未読メール取得 → 添付（pdf/画像/xlsx/docx、50MB以下）を抽出
2. **送信元メールアドレスで出展社を特定**:
   - `users.email` と一致 → そのユーザー・組織に紐づけ
   - 一致しない → 取り込まず、管理者宛に「未登録アドレスからのメール」通知を作成して既読化
3. カテゴリ判定: 件名に含まれるカテゴリ名（例: 件名「電気申込 3コマ分」→「電気申込」）。
   判定できなければ **その展示会の必須カテゴリにはせず「その他」扱いにできないため**、
   ドキュメントは作るが submission_category は「メール受信（未分類）」という専用カテゴリを
   シード的に自動作成して紐づけ、管理者がレビュー画面から振り替える（振替APIは既存documentsのPATCHを拡張）
4. 展示会の特定: activeな展示会が1つならそれ。複数あれば件名に展示会名が含まれるものを優先、
   判定不能なら管理者通知だけ作って保留（誤登録より安全側に倒す）
5. Document作成時 `source_channel="email"`（カラムは既存・デフォルトweb_upload）→ 既存のAI解析パイプラインへ
6. 取り込んだメールは既読化＋ラベル `DOSL-HUB取込済` を付与（多重取込防止。message_idも
  `documents` に `source_message_id` カラム追加で二重ガード）

### DBスキーマ変更（本番SQLiteにALTER必要）
```sql
ALTER TABLE documents ADD COLUMN source_message_id VARCHAR(300);
```
（README共通ルール5の手順で本番にも適用）

### UI
- 書類一覧に「経路」列（Web/メール）を追加（source_channelを表示するだけ）
- カテゴリ「メール受信（未分類）」の書類は管理画面の書類詳細から「カテゴリを変更」できるようにする

### 返信（自動応答）は作らない
Phase 2では取り込みのみ。受領通知メール送信は未実装のメール送信基盤ごと別タスク
（→ 05_小粒改善リストの「初期パスワードのメール送信」と同時に設計する）。

## 検証
1. ユニット的検証: mail_ingest の判定ロジック（送信元一致/不一致・件名カテゴリ判定）をpytestで
2. 実メール: テストGmailに自分で添付送信→2分以内にDocument化→AI解析→管理画面に出る
3. 未登録アドレスから送信→取り込まれず管理者通知が出る
4. 同じメールが二重取込されない（再起動しても）

## デプロイ
- requirements.txt に google-api-python-client / google-auth 追加 → VMでpip install
- .env にGmail認証3変数＋MAIL_INGEST_ENABLED=true を追記（上書き禁止）
- 本番DBにALTER実行
