# 指示書05: 小粒改善リスト

急ぎではないが把握済みの改善点。1件ずつ独立に実装・コミットできる。

## 5-1. 通知のポーリング
- 現状: admin.htmlの通知ベルは手動リロード/操作時のみ更新
- 対応: `setInterval(loadNotifications, 60000)` を追加するだけ。ただしタブが非表示のときは
  スキップ（`document.visibilityState !== 'visible'` でreturn）

## 5-2. 「解析失敗」と「差し戻し」の分離
- 現状: どちらも document.status="error"（UI表示は「差し戻し」）
- 対応: 解析失敗は `status="analysis_failed"` に分離。app.js の STATUS_LABELS に
  `analysis_failed: {text:'解析失敗', cls:'status-error'}` を追加。
  書類一覧のフィルタにも追加。**既存データのstatusは変換不要**（新規発生分から分かれればよい）
- 注意: documents.py・ai_analyzer.py・reviews.py の status="error" 代入箇所のうち
  ai_analyzer.py（解析例外時）だけを変更する

## 5-3. AIレビュー画面にdesign_specを表示
- 現状: レビュー画面（admin.htmlのrenderReviewDetail）は注文品目の編集のみ。
  ブース設営書類のレビュー時に design_spec（寸法・素材）が見えない
- 対応: structured_data.design_spec があれば読み取り専用カードで寸法・素材・電気要件を表示
  （編集は承認後に設計仕様タブで行う運用。レビュー画面での編集は作らない）

## 5-4. 初期パスワードのメール送信（Phase 2）
- 現状: 出展申込の承認・ユーザー作成・パスワード再発行で、パスワードは画面表示のみ
- 対応: メール送信基盤の導入とセット。**04_メール受信.md のGmail運用が決まってから**、
  同じGoogleアカウントで Gmail API の send を使う（新規SMTP契約はしない）。
  送信箇所は applications.py の approve / admin_users.py の create_user・reset_password の3箇所
- 送信可否は .env `MAIL_SEND_ENABLED`（デフォルトfalse）。失敗しても処理は成功させ、
  画面表示のフォールバックは残す

## 5-5. モバイルSafariのカメラ撮影 実機検証
- 実装済み（capture属性）だが実機未検証。iPhoneで https://34-168-97-181.sslip.io を開き、
  出展社アカウントで撮影アップロード→解析まで通す。問題があればここに追記

## 5-6. 監査ログ（audit_logs）の記録開始
- 現状: テーブルだけあり誰も書いていない
- 対応: まず「レビュー承認/差し戻し」「ユーザー作成/無効化/PW再発行」「組織削除」の
  5操作だけ記録する小さなヘルパー `services/audit.py` を作る（全操作網羅はしない）
