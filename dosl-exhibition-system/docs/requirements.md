## 1. システム概要

| 項目 | 内容 |
|------|------|
| システム名 | DOSL Exhibition System |
| 種別 | マルチテナント型 展示会 事前登録・受付チェックインシステム |
| フロントエンド | Next.js 14 / React 18 / Tailwind CSS |

#### 同伴者情報（表示制御: `form_fields.companions` + `features.companion`）

| # | フィールド名 | DB列名 | テーブル | 型 | 必須 | 最大文字数 | バリデーション |
|---|-------------|--------|---------|-----|------|-----------|--------------|
| 17 | 同伴者氏名 | companions[].name | registrations (JSONB) | TEXT | 同伴者追加時は必須 | 50 | 空文字不可 |
| 18 | 同伴者カナ | companions[].name_kana | registrations (JSONB) | TEXT | 任意 | 50 | |
| 19 | 同伴者会社名 | companions[].company | registrations (JSONB) | TEXT | 任意 | 100 | |

- 同伴者の最大人数: `form_fields.companions.max`（デフォルト: 4名）
- 同伴者配列の最大件数をサーバー側でも検証

#### フィールド表示制御の仕組み

各展示会の `form_fields` JSONB で、フィールドごとに以下を制御:

```json
{
  "company_name": { "visible": true, "required": true },
  "phone":        { "visible": true, "required": false },
  "postal_code":  { "visible": false, "required": false }
}
```

- `visible: false` → フォームに表示しない
- `required: true` → フォームで必須マーク表示、サーバー側でも空チェック

### 4.2 バリデーション仕様

#### クライアント側バリデーション（登録フォーム）

| チェック | 実装方式 | 対象 |
|---------|---------|------|
| 必須チェック | HTML `required` 属性 | メール、姓、名、form_fieldsでrequired=trueの項目 |
| メール形式 | HTML `type="email"` | メールアドレス |
| 電話番号形式 | HTML `type="tel"` | 電話番号 |
| 最大文字数 | HTML `maxLength` 属性 | 全テキスト項目 |
| チケットコード | maxLength=8, 大文字自動変換 | チェックイン手動入力 |

**現状の実装状況:**
- `maxLength` 属性: **実装済** — 全テキスト項目（登録フォーム・編集モーダル・ログイン）
- フォーマットチェック: **実装済** — 電話番号・郵便番号に `pattern` 属性
- 送信前のカスタムバリデーション: HTMLネイティブ検証＋サーバー側検証で担保

### 4.3 登録処理フロー

```
1. バリデーション（必須項目チェック）
2. 展示会の存在・公開状態チェック（status = 'published'）
3. 登録上限チェック（max_registrations）
4. 来場者の UPSERT（emailで一意判定）
5. 重複登録チェック → 既存なら既存チケットコードを返却
6. チケットコード生成（DB関数: 8文字英数字）
7. 登録レコード作成（status = 'confirmed'）
8. セミナー予約作成（seminar_ids指定時）
9. 確認メール送信（非同期・失敗しても登録は成功）
10. チケットコード・登録IDを返却
```

### 4.3 チケットコード仕様

- 8文字の英数字（大文字）
- 使用文字: `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`（0/O、1/I/L を除外）
- DB関数 `generate_ticket_code()` で暗号学的に安全に生成

- チケットコードの大文字表示
- QRチケット表示ページへのリンク

```

## 9. 受付チェックイン

### 9.1 入力モード

| モード | 機能 |
|--------|------|
| QRカメラ | スマホ/PCのカメラでQRコード読取。背面カメラ自動選択、カメラ切替対応 |
| 手動入力 | チケットコードを手打ち（8文字、大文字自動変換） |

### 9.2 チェックイン処理フロー

```
1. ticket_code で登録情報を検索
2. ステータスチェック（cancelled → エラー）
3. 最新の entry_log を確認
   - 最後が 'entry' → already_entered = true（再入場）
   - 最後が 'exit' or ログなし → already_entered = false（初入場）
4. entry_log を INSERT（action='entry', method='qr'/'manual'）
5. 結果を返却
```

### 9.3 結果表示

| 状態 | 表示 |
|------|------|
| 初入場 | 緑色ボーダー、氏名・会社名・種別バッジ・同伴者 |
| 再入場 | 黄色ボーダー、「再入場（既に入場済み）」表示 |
| エラー | 赤色ボーダー、エラーメッセージ |

### 9.4 重複スキャン防止

- 同一QRコードの連続読取を3秒間ブロック

### 9.5 チェックイン履歴

- 直近50件を画面下部に表示
- チケットコード、氏名、会社名、種別、再入場バッジ

| 変数 | 必須 | 説明 |

1. ticket_code（8文字英数字）・seminar_id（UUID）検証
2. セミナー存在チェック。draft / cancelled は受付拒否
3. チケットから登録を取得。cancelled は拒否
4. 登録の展示会 ≠ セミナーの展示会 → 「別の展示会のチケットです」
5. 予約（seminar_bookings）取得。なし → 「このセミナーの予約がありません」
   予約が cancelled / waitlisted → 拒否
6. checked_in_at 未設定なら現在時刻を記録。設定済みなら already_checked_in=true を返す（上書きしない）
```

予約なし来場者の当日飛び込み受付（ウォークイン）は**未実装**（将来検討）。

### 21.4 聴講実績CSV

列: セミナー / チケットコード / 姓 / 名 / セイ / メイ / 会社名 / メールアドレス / 予約ステータス / 聴講（聴講済・未聴講） / チェックイン日時（JST） / 予約日時（JST）。
UTF-8 BOM付き・数式インジェクション対策は登録者CSVと同一（src/lib/csv.ts に共通化）。

### 21.5 認証

管理APIすべて `requireAdminApi()` 必須（管理者・スタッフ用。出展社向けではない）。

## 22. リードリトリーバル（GATEオプション・2026-07-08 実装）

出展社がブースで来場者のQR入場証をスキャンし、リード（来場者情報）を取得する機能。**展示会ごとに `features.lead_retrieval` フラグでON/OFF**。収益モデルは出展社課金（スキャンアプリ利用料×出展社数）。

DB: `supabase/migrations/005_gate_options.sql`（exhibitors / exhibitor_leads）。

### 22.1 出展社認証

- Supabase Auth は使わず、出展社ごとの**アクセスコード**（12文字英数字、0/O・1/I/L除外、約60bit）で認証
- コードは管理者が `/admin/exhibitors` で発行・再発行。httpOnly Cookie（14日）に保持し、**毎リクエストDB照合**（is_active=false やオプションOFFで即時遮断）
- ログインAPIはIPごと10回/15分のレート制限（総当たり対策）

### 22.2 出展社フィールド定義

| # | フィールド | 必須 | 最大 | バリデーション |
|---|-----------|------|------|--------------|
| 1 | 出展社名 name | **必須** | 100 | 前後トリム |
| 2 | ブース番号 booth_number | 任意 | 20 | |
| 3 | 担当者名 contact_name | 任意 | 50 | |
| 4 | 担当者メール contact_email | 任意 | 254 | メール形式・小文字化 |
| 5 | アクセスコード access_code | 自動発行 | 12 | `^[A-Z0-9]{12}$`（DB CHECK） |
| 6 | 有効フラグ is_active | - | - | boolean |

### 22.3 リードスキャン（POST /api/exhibitor/scan）

```
1. チケットコード（8文字英数字）検証
2. 登録を取得。cancelled は拒否
3. 登録の展示会 ≠ 出展社の展示会 → 「この展示会のチケットではありません」
4. exhibitor_leads に INSERT。重複（同一来場者の再スキャン）は
   一意制約23505を捕捉し already_scanned=true で既存リードを返す
5. 来場者情報（氏名・カナ・会社・部署・役職・メール・電話）を返す
```

### 22.4 リード一覧・商談メモ・CSV

- 一覧はスキャン日時降順。詳細展開で連絡先・業種・来場目的を表示
- 商談メモ（500文字以内）はリードごとに編集可。**自社のリードのみ**（exhibitor_id照合）
- CSV列: スキャン日時（JST）/ 姓 / 名 / セイ / メイ / 会社名 / 部署 / 役職 / メールアドレス / 電話番号 / 業種 / 来場目的 / メモ。BOM・数式インジェクション対策は共通（lib/csv.ts）

### 22.5 個人情報の扱い（運用注意）

- 出展社は「自社ブースでスキャンした来場者」の情報のみ閲覧できる（全来場者一覧は見えない）
- 来場者への「入場証提示＝出展社への情報提供に同意」の明示は登録フォーム側の規約文言で行う（**未実装・運用課題**）
